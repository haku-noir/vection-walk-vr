## 1. 中核となる設計

### 1.1 四角錐（箱）とは

- 頂点が**視点位置**を表す仮想の四角錐。頂点から距離 d₁, d₂ の位置に矩形断面を2枚描く。
- **自分の視野に描かれる箱** = 頂点が**相手**の視点（`Cone_Other`）
- **相手の視野に描かれる箱** = 頂点が**自分**の視点（`Cone_Self`）
- 自分の錐は自分の視点＝頂点にあるため自分からは見えない。ゆえに相手視野側に描く必要がある。

### 1.2 何が新しいか

従来は**地**（背景オプティカルフロー）の一致によって視点一致を目指していた。
本案は**図**である箱の一致に置き換える。箱の一致は視点一致と**幾何的に等価**であり、
代理指標ではない。これにより、手の追従で使われる図の誘導手法（4ストローク、ワブル）が
視点追従にも流用可能になる。

### 1.3 幾何的性質（合意済み）

観察者 O、錐の頂点 P、開き半角 α、断面距離 d₁ < d₂ とする。

| 誤差 | 2断面の見え | 成分の性質 |
|---|---|---|
| ヨー誤差 θ | 両断面が同じ角度だけ一緒に動く（同心を保つ） | **同相成分** |
| 横並進誤差 δ | 近断面 atan(δ/d₁)、遠断面 atan(δ/d₂) で移動量が違う → 同心が崩れる | **差動成分** |
| 前後誤差 D | 位置は動かず、2断面の**見かけ大きさの比**が変わる | スケール成分 |

- 誤差ゼロで2断面は完全に重なり、**1枚の矩形として静止する**（ヌル指示）。
- 見かけ大きさ比 r = d₁(D+d₂) / d₂(D+d₁)、D=0 で r=1。
- 前後感度 |dr/dD|(D=0) = **(d₂−d₁)/(d₁d₂)** ← パラメータ設計の指針

### 1.4 時分割が自動生成するワブル

自分が A、相手が B = A+δ のとき、

- 自分の視野フレーム：頂点 B の錐が **+δ 方向**にずれて見える
- 相手の視野フレーム：頂点 A の錐を B から見るので **−δ 方向**にずれて見える

→ 交互提示の間、箱は**振幅 2δ で左右に振動**し、δ→0 で振動が消える。
ワブルは外から掛けなくても時分割から生じる。

この構造は **SI2025 の逆位相2群オプティカルフローと同型**であり、
4ストロークの極性がその「規定因」として働く。

### 1.5 2つの箱は冗長ではない — 視覚運動極性が逆

| 箱 | 描画先 | 自分が右を向いたとき | 極性 |
|---|---|---|---|
| `Cone_Other` | ライブ視野 | 背景も箱も左へ流れる | **正常**（閉ループ成立、運動視差も正しい） |
| `Cone_Self` | ゴースト視野 | 背景は不変、箱だけ右へ動く | **反転**（逆運動に対する追従は困難） |

先生の指摘「箱にしたことによってオプティカルフローが逆運動をしている。
逆運動に対する追従動作というのが、人は苦手」に対応。

### 1.6 前後の符号は原理的に多義 → **稜線オクルージョンで解消（決定）**

- 頂点が奥 → 遠断面が大きく見える
- 頂点が手前 → 近断面が大きく見える

**どちらも「入れ子の2矩形」という同じ像**になり、近／遠の帰属だけが反転する。
ネッカーキューブと同型。両眼視差は非対応（07 既知の制限）のため視差では解けない。
コースは +Z 進行なので**前後誤差が主要成分**であり、無視できない。

**採用: 稜線オクルージョン方式**

頂点方向へ伸びる4本の側稜と2枚の断面枠を、太さを持つ3Dジオメトリとして描画し、
**箱カメラ内で ZWrite ON / ZTest LEqual** とする。線が交差する箇所で近い線が遠い線を隠すため、
ネッカーキューブ的な反転が解消される。線は細いので背景の遮蔽はほとんど生じない。

**この方式を採用した理由は、4ストロークの輝度変調方式（§2.3）と両立するため。**
当初案の「近断面／遠断面の別色」は色情報を使うため輝度変調と排他になり、
**4ストローク条件でだけ奥行きが多義になる**という条件間の交絡を生む。
稜線オクルージョンは形状による手がかりなので、全条件で同じ奥行き手がかりが提供される。

不採用にした手段（参考、パラメータとしては残す）:

- 近断面と遠断面の**別色・別線種**: 輝度変調と排他になるため既定では使わない
- 断面を3枚以上にして**密度勾配**を作る: 輝度変調とは両立するが遮蔽が増える。補助手段
- **運動視差**: `Cone_Other` では自然に効くが、`Cone_Self` は極性反転のため誤って解かれる。
  条件間で非対称なので、これに依存した設計にはしない

## 2. 実装アーキテクチャ

### 2.1 カメラ・レイヤ構成

| カメラ | 姿勢 | Culling Mask | 出力 RT |
|---|---|---|---|
| `LiveBGCam`（既存 CenterEyeCapture） | ライブ頭部 | 環境のみ | `BG_Live` |
| `GhostBGCam`（既存 GhostCamera） | 収録軌跡 | 環境のみ | `BG_Ghost` |
| `LiveBoxCam`（新規） | ライブ頭部 | `ConeOther` のみ・透明クリア | `Box_Other` |
| `GhostBoxCam`（新規） | 収録軌跡 | `ConeSelf` のみ・透明クリア | `Box_Self` |

- `Cone_Other` は GhostCamera の姿勢に追従（Layer: `ConeOther`）
- `Cone_Self` は CenterEyeAnchor の姿勢に追従（Layer: `ConeSelf`）
- 断面は頂点から 1〜3 m 先にあるためニアクリップ問題は生じない
- **箱カメラは独自の深度バッファを持つ**（環境を描画しないため）。錐の内部だけで
  ZWrite/ZTest が働き、稜線オクルージョン（§1.6）が成立する。合成時に箱 RT を背景の上に
  重ねるので、「環境に埋もれない」性質は保たれる。ZTest Always は**不要**

### 2.2 2チャンネル独立合成

| チャンネル | 選択肢 |
|---|---|
| **背景** | Live固定 / Ghost固定 / 矩形波交替(f_bg) / 4ストローク(f_bg, 極性) |
| **箱** | Off / Other固定 / Self固定 / 矩形波交替(f_box) / 4ストローク(f_box, 極性) |

周波数・極性はチャンネルごとに独立。
既存 `FourStrokeCompositor` を2インスタンス化し、合成シェーダを4入力に拡張する。

### 2.3 箱の4ストローク — 輝度変調方式が必要

4ストロークの原理は反転ペア間の**輝度相関が負**になることに依存する（08 参照）。
箱は透明背景上の疎なワイヤフレームであり、反転すべき地の面積がないため
通常の反転では負相関が作れない。

そこで箱を「色」ではなく**背景に対する輝度変調**としてレンダリングする：

```
final = BG + boxMask × sign × Δ
```

反転位相で sign = −1 とすることで、下地が何であっても線と地のコントラストが反転する。
合成シェーダ内で完結し、追加描画パスは不要。

この方式は色情報を輝度に潰すため、当初案の「近断面／遠断面の別色」とは両立しない。
§1.6 で奥行き手がかりを**稜線オクルージョン（形状による手がかり）**に変更したことで、
この衝突は解消済み。箱は**単色**でよく、4ストロークの ON/OFF によらず同じ奥行き手がかりが提供される。

## 3. パラメータ定義

### 3.1 箱の幾何

| パラメータ | 記号 | 既定値 | 範囲 | 根拠 |
|---|---|---|---|---|
| 近断面距離 | d₁ | **1.0 m** | 0.8–1.5 | 0.8 m 未満は輻輳・調節矛盾で不快。前後感度は d₁ が小さいほど高い |
| 遠断面距離 | d₂ | **3.0 m** | 2.0–5.0 | 前後感度 (d₂−d₁)/(d₁d₂) = 0.67/m。d₂ 増で感度向上、ただし遠断面が小さくなる |
| 開き半角 | α | **15°**（見かけ直径30°） | 10–25° | 中心視〜傍中心視に収まり、周辺の背景フローを遮らない（先生「なるべく視野中央付近で」） |
| 断面半幅 | w(d)=d·tanα | d₁で0.27 m / d₂で0.80 m | — | α から従属 |
| 断面枚数 | N | **2** | 2–4 | 3枚以上は密度勾配による補助手がかり（1.6） |
| 線幅 | — | **0.3°**（角度指定） | 0.15–0.5° | 距離によらず一定太さにする。各断面のワールド線幅は 2·d·tan(幅/2) |
| 線の色 | — | **単色（白）** | — | 輝度変調（2.3）と両立させるため色分けはしない |
| **稜線の描画** | — | **ON** | ON/OFF | **前後多義性の解消手段（1.6 採用案）**。頂点方向へ伸びる4本の側稜 |
| 深度処理 | — | **ZWrite ON / ZTest LEqual**（箱カメラ内） | — | 線の交差部で近い線が遠い線を隠す。環境の上への重畳は合成段で担保 |
| 別色モード | — | **OFF** | ON/OFF | 近＝シアン／遠＝マゼンタ。4ストロークとは排他。比較条件としてのみ残す |
| 輝度変調量 | Δ | **0.35**（0–1輝度） | 0.2–0.6 | 4ストローク時のコントラスト（2.3） |

**感度の確認（既定値、δ=0.1 m のとき）**

- 近断面 atan(0.1/1.0) = 5.7°、遠断面 atan(0.1/3.0) = 1.9° → **差動 3.8°**（十分検出可能）

### 3.2 箱の姿勢処理

| 成分 | 既定 | 選択肢 | 根拠 |
|---|---|---|---|
| ヨー | **そのまま** | raw / LPF / zero | 目標自由度そのもの |
| ピッチ | **LPF 0.5 Hz** | raw / LPF / zero | 歩行の上下動を除去 |
| ロール | **ゼロ化** | raw / LPF / zero | 歩行由来のロール振動（1〜2 Hz）が、操作したいワブル・4ストロークと同帯域で**交絡する**ため。ロールは目標自由度でもない（主指標は errXZ） |

> 注: ロール除去の根拠は「相手のロールは無関係だから」ではなく「交絡するから」。
> 非対称系（大山案）の議論をそのまま持ち込まないこと。

### 3.3 提示パラメータ

| パラメータ | 既定値 | 範囲 | 根拠 |
|---|---|---|---|
| 背景切替周波数 f_bg | **5.0 Hz** | 3.0–7.5 Hz | paper_draft_v2 の凝化帯 T=66.7–166.7 ms に対応（f = 1/2T）。5.0 Hz は T=100 ms で凝化帯中央 |
| 箱切替周波数 f_box | **f_bg と同期** | 0.1–10 Hz | 独立操作も可能にする |
| デューティ比 | **50%** | 固定 | 既存 ViewSwitcher 仕様 |
| 背景4ストローク極性 | **Zero** | Enhance/Zero/Reversal | — |
| 箱4ストローク極性 | **Zero** | Enhance/Zero/Reversal | — |

> **安全**: 3.0–7.5 Hz は光感受性発作のリスク帯域に直撃する。倫理審査で周波数範囲を
> 明示し、既存のポーズ機構（O / B ボタンで視野マスク）を必ず維持すること。

### 3.4 実験パラメータ

| パラメータ | 既定値 | 選択肢 |
|---|---|---|
| 初期オフセット（横） | 0 m | 0 / 0.3 / 0.6 m |
| 初期オフセット（前後） | 0 m | 0 / 0.5 / 1.0 m |
| 初期オフセット（ヨー） | 0° | 0 / 10 / 20° |
| 環境密度 | 高密度 | 高 / 低 / なし（1/2/3キー） |

## 4. 条件別の予測

| 箱条件 | 極性 | 予測 |
|---|---|---|
| Off | — | ベースライン |
| Other のみ | 正常 | **追従が最も容易**。運動視差で前後多義性も解ける |
| Self のみ | 反転 | 追従が困難。前後も誤知覚しうる |
| 両方（ワブル） | 交互 | 多義的。SI2025 の逆位相2群と同型で、極性反転が起きる |
| 両方＋4ストローク | 一義化 | 極性が規定され、反転が抑制される |

最下段が成立すれば、**SI2025 の結果（同期刺激による極性の一義化）が
視点追従の文脈で再現された**ことになる。

## 5. 実験段階

### 段階1：極性の効果（パイロット 2〜3名）

- 背景 = 矩形波交替に固定、箱 = {Off, Other のみ, Self のみ, 両方} の4条件
- 目的: 「自分の箱は本当に追従を悪化させるか」の判定
- ここで以降の条件数を半減できる

### 段階2：4ストロークの効果

- 段階1の最良条件に対し、箱チャンネルへ {Enhance, Zero, Reversal} を適用
- 背景側の4ストロークとの交互作用は、必要なら段階2b として分離

### 段階3：誤差依存性

- 初期オフセットを与え、誤差の大小で最適条件が入れ替わるかを検証
- **顕著性シグモイド制御案**（大誤差では表示型＝箱を明示、小誤差では引き込み型＝
  箱を減衰させワブル成分のみ残す）の直接検証にあたる

### 実装上の決定（仕様に明記が無く、実装側で決めた点）

- **側稜の範囲**: 既定は角錐台の側稜（近断面〜遠断面）。`Ridge Extend To Apex` を
  ON にすると頂点まで延ばせる（頂点＝相手の視点位置なので線がカメラ直近まで来る）
- **箱の合成方式**: 4ストロークの ON/OFF によらず常に輝度変調
  （非4ストローク条件は `sign = +1` 固定）。条件間で箱の見えの原理を変えないため
- **箱の4ストロークの入力割り当て**: 背景が `C = ライブ / D = 収録` なのに合わせて
  `C = Cone_Other / D = Cone_Self`。**これが逆だと Enhance と Reversal のラベルが入れ替わる**ので、
  パイロットで見えの向きを確認すること
- **f_bg の持ち主**: 既存 `ViewSwitcher.switchFrequency`（既定 1.0Hz のまま）。
  §3.3 の既定 5.0Hz は実験時に設定する
- **2つの錐のパラメータ同期**: 錐は独立したコンポーネントなので、片方だけ設定を変えると
  誤差ゼロでも2つの箱に差が残り、時分割で消えるはずのワブル（§1.4）が消えなくなる。
  これを防ぐため `Cone_Self` が `Cone_Other` から幾何・見た目・姿勢処理の条件を引く
  （`ConeGuide.mirrorFrom`）。編集は `Cone_Other` 側で行う

### 未実装（仕様の未決事項に対応）

- §7-1 の「2つの箱を**同時に重ねて**差を見せる」案は未実装。現在の「両方」は
  §1.4 / §2.2 に従い**時分割の交替**（`SquareAlternate`）。
  同時提示にする場合は合成シェーダ側は両方の重みを 1 にするだけでよく、
  選択肢を1つ足す程度の小改修で済む
- §7-3 の稜線による視野の遮蔽量は、HMD 実機での確認事項として残っている
